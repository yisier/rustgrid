# PostgreSQL 引擎

`rustgrid-postgresql` 是 RustGrid 的原生 PostgreSQL 驱动，基于 **sqlx 0.9** 的 `postgres`
feature（复用工作区的 `tls-rustls-ring`，不引入新的原生编译依赖）。它与
MySQL / MariaDB / SQLite / SQL Server 同级，复用 `rustgrid-core` 的 `Driver` / `Connection`
抽象，UI 无需任何改动。

## 连接

| 字段 | 说明 |
|---|---|
| 主机 / 端口 | 默认 `5432` |
| 用户名 / 密码 | 密码在连接时提示，**从不写入 profile**（加密存于 `secrets.json`） |
| 数据库 | profile 的默认库；留空回退 `postgres` |

TLS 五档映射到 `PgSslMode`：`Disabled→Disable`、`Preferred→Prefer`、`Required→Require`、
`VerifyCa→VerifyCa`、`VerifyIdentity→VerifyFull`，`ssl_root_cert` / `ssl_client_cert` /
`ssl_client_key` 均接线。rustls 下 `VerifyFull` 需要 root cert。

隧道（SSH / SOCKS5 / HTTP）通过共享的 `rustgrid-tunnel` 复用，与 MySQL 相同。
连接超时、`keepalive`、只读会话（`SET default_transaction_read_only = on`）、
`statement_timeout` 与 `init_sql` 都在每条池连接上生效。

## 架构要点

- **按数据库分片的连接池。** PostgreSQL 的连接绑定到单个数据库，无法跨库查询。驱动维护一个
  按需懒建的 `PgPool` 表：默认库保持常驻（5 条连接），其它库最多 2 条并带短 `idle_timeout`，
  池数超过上限时按需驱逐，避免展开大量库时耗尽服务端 `max_connections`。
- **对象名 schema 限定。** `list_tables` / `list_routines` / `list_schemas` 返回 `public.users`
  这类名字，连接树据此插入 **数据库 → schema → 表/视图/函数** 层级。系统 schema
  （`pg_catalog` / `information_schema` / `pg_toast*` / `pg_temp*`）默认隐藏。
- **目录查询走 `pg_catalog`。** 不用 `information_schema.tables`（它只暴露当前用户有权限的对象），
  因此非超级用户也能看到全部表。
- **多语句脚本交给服务端。** `execute_query_many` 在**一条 pinned 连接**上用
  `raw_sql(...).fetch_many` 执行整段脚本，`$$ … $$` / `$tag$ … $tag$` 函数体、`BEGIN; … COMMIT;`
  事务、`SET LOCAL`、临时表都由服务端解析，语义正确。客户端切分只用于填 `statement` 文本与
  零行结果集的列元数据（用 `pool.prepare`，不是被 `offline` feature 门控的 `describe`）。

## 强类型：绑定参数一律 `CAST`

PostgreSQL 是强类型引擎，而 core 交给驱动的值全是字符串。按 `String`（TEXT）绑定会让
`integer` / `boolean` / `numeric` / `timestamptz` 列直接报类型不匹配。因此驱动在生成 SQL 时
按列的 `format_type` 加显式转换：

```sql
UPDATE "public"."t" SET "n" = CAST($1 AS integer) WHERE "id" = CAST($2 AS integer)
```

过滤树同样对每个绑定值加 `CAST`；`NULL` 仍走 `IS NULL`，绝不绑定空串。

## 读路径：列投影为文本

结果值的格式由**这条语句是否带绑定参数**决定：带绑定（如翻页时的过滤）走扩展协议 → 二进制
格式，此时 MySQL 式「未检查字节转 UTF-8」的兜底取不到 `numeric` / `uuid` / `json(b)` / 数组 /
`inet` 的文本。因此 `fetch_page` 把每个列投影成 `"c"::text` 再按 `format_type` 还原成
`CellValue`；备份的流式读与任意 SQL（简单查询协议，本就是文本）按类型名还原。

## 库管理

`CREATE DATABASE` / `DROP DATABASE` **不能在事务里**，也不能连着目标库执行，因此它们走**维护库**
的连接（优先 `postgres`，其次默认库，再退 `template1`）。建库支持 `ENCODING` / `LC_COLLATE`
（+ `LC_CTYPE`）/ `OWNER`；改库**只支持 OWNER**，尝试改 encoding/collation 会返回明确错误。
`character_sets` 由 `pg_encoding_to_char` 枚举，`collations` 取 `pg_collation` 中
`collprovider = 'c'` 的 libc locale 串（ICU 条目的名字不是合法 `LC_COLLATE`）。

## 表 DDL 与设计器

PostgreSQL 没有 `SHOW CREATE TABLE`，表结构由 `pg_catalog` 拼装（`pg_attribute` / `pg_attrdef` /
`pg_constraint` / `pg_index` / `pg_trigger`）。`auto_increment` 识别 `serial`（默认值
`nextval(...)`）与 `GENERATED … AS IDENTITY`，新建列生成 `GENERATED BY DEFAULT AS IDENTITY`。
修改生成 `ALTER TABLE` 序列（增删列 / 改类型 / 空值 / 默认值 / 主键 / 索引 / 外键）。

## 视图与例程

- 视图定义来自 `pg_get_viewdef`；保存优先 `CREATE OR REPLACE VIEW`，列集变化导致失败时退化为
  `DROP VIEW` + `CREATE VIEW`。
- 例程按 `(name, 参数类型)` 唯一，驱动把 schema 与签名编进名字（`public.get_user(integer)`），
  `list_routines` 与 `list_routine_infos` 返回同样的名字，定义来自 `pg_get_functiondef`。
- `list_events` 返回空（PostgreSQL 无事件调度器）。

## 备份与还原

`.rgbak` 的表数据由 `stream_table_rows` 流式渲染成 PostgreSQL 字面量（`'…'`、`NULL`、
`true/false`、`bytea` 的 `'\x…'`）。还原时：`GENERATED ALWAYS AS IDENTITY` 列用
`OVERRIDING SYSTEM VALUE` 显式写入，`serial` / identity 列在导入后用 `setval` 重置序列
（空表用 `coalesce` 兜底，不会报错）。

## 已知限制

- **行数是估算值**：表列表的「行」来自 `pg_class.reltuples`（未 ANALYZE 时为 `-1`，已归零），
  不是精确 `count(*)`。
- **视图 / 外部表分页无 `ctid`**：无主键且无排序时，基表 / 分区表 / 物化视图用 `ORDER BY ctid`
  保证稳定；视图与外部表没有 `ctid`，退化为不带 `ORDER BY` 的 `LIMIT/OFFSET`。
- **非超级用户的会话数偏小**：`pg_stat_activity` 看不到他人的会话。
- **对象级权限**只能表达 core `Privilege` 枚举的子集（`TRUNCATE` / `USAGE` / `CONNECT` 等无对应
  项），其余在驱动内部以字符串处理。
- **时间/数值精度**：`numeric` / `decimal` / `money` 以精确文本或浮点呈现，`date` / `time` /
  `timestamp` / `timestamptz` 按 `chrono` 解码后格式化。

## 测试

纯函数单测在各源文件的 `#[cfg(test)] mod tests` 中（标识符引用、脚本切分含美元引用、过滤 CAST、
分页、DDL 生成、字面量、类型映射、例程名解析）。

真机集成测试（默认 `#[ignore]`）：

```powershell
$env:RUSTGRID_PG_PASSWORD="postgres"
cargo test -p rustgrid-postgresql -- --ignored
```

可用环境变量：`RUSTGRID_PG_HOST` / `PORT` / `USER` / `PASSWORD` / `DATABASE`。一次性服务端：

```bash
docker run -d --name rg-pg -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:17
```

覆盖：连接、列库 / 列 schema / 列表 / 列列、分页（含过滤与排序）、强类型列的增删改、
任意 SQL（多语句、`$$` 函数、事务）、schema 管理、表设计器、视图、例程、角色、备份 / 还原。
